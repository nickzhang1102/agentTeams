## 概述

Agent Teams（团队协作）功能允许您同时使用多个 AI Agent 并行处理任务，获得多角度的分析和建议。

## 什么是团队协作？

团队协作模式让您可以：

- **并行处理**：多个 Agent 同时处理同一任务
- **多角度分析**：从不同专业视角获得建议
- **独立结果**：每个 Agent 的结果独立展示
- **快速反馈**：并行执行节省时间

## 开始使用

### 访问团队功能

1. 登录 Agent Teams System
2. 进入聊天页面
3. 在页面顶部找到团队选择器
4. 点击下拉菜单查看可用团队

### 团队选择器界面

团队选择器分为两个部分：

**1. 单个 Agent**
- 列出所有可用的单个 Agent
- 选择后使用传统单 Agent 模式

**2. 团队协作**
- 代码审查团队
- 需求分析团队
- 架构设计团队
- 您的自定义团队

## 使用步骤

### 步骤 1: 选择团队

1. 点击团队选择器
2. 在"团队协作"部分选择合适的团队
3. 查看团队信息卡片：
   - 团队名称
   - 团队描述
   - 成员列表

### 步骤 2: 输入消息

1. 在输入框中输入您的请求
2. 可以包含代码、需求描述、问题等
3. 支持上传文件（如果需要）

### 步骤 3: 发送并等待

1. 点击"发送"按钮
2. 观察团队执行进度：
   - 显示 "团队开始执行"
   - 多个 Agent 并行响应
   - 结果逐步显示在折叠面板中

### 步骤 4: 查看结果

1. 点击各个 Agent 的折叠面板
2. 查看详细结果：
   - Agent 名称
   - 执行时间
   - 置信度分数
   - Markdown 格式的内容
3. 成功/失败状态标签

### 步骤 5: 综合分析

- 比较不同 Agent 的观点
- 综合多个角度的建议
- 做出更好的决策

## 最佳实践

### 1. 选择合适的团队

- **代码审查** → 使用代码审查团队
- **需求讨论** → 使用需求分析团队
- **架构设计** → 使用架构设计团队
- **简单问答** → 使用单个 Agent

### 2. 提供清晰的输入

- 清晰描述任务目标
- 提供足够的上下文
- 包含必要的代码或文档
- 明确期望的输出格式

### 3. 合理使用团队

- 不要滥用团队模式（简单任务用单 Agent）
- 团队规模建议 2-10 个 Agent
- 避免过于频繁的团队调用

### 4. 综合分析结果

- 比较不同 Agent 的观点
- 关注置信度分数
- 注意失败状态的错误信息
- 综合考虑多个角度

## 性能考虑

### 执行时间

- 团队执行时间 ≈ 最慢 Agent 的时间
- 通常 3-10 秒（取决于 Agent 数量和复杂度）
- 并行执行，不是串行

### 资源消耗

- 每个 Agent 独立调用 Claude API
- 消耗 API 配额 = Agent 数量
- 建议合理使用

## 故障排查

### 问题 1: 团队选择器为空

**可能原因**：
- 未登录
- 网络连接问题

**解决方案**：
- 检查登录状态
- 刷新页面
- 检查网络连接

### 问题 2: Agent 执行失败

**可能原因**：
- API 调用超时
- 网络问题
- Agent 服务异常

**解决方案**：
- 查看错误信息
- 重试请求
- 使用单个 Agent 模式

### 问题 3: 结果显示不完整

**可能原因**：
- SSE 连接中断
- 浏览器兼容性问题

**解决方案**：
- 刷新页面
- 使用现代浏览器（Chrome、Firefox、Edge）
- 检查浏览器控制台错误

## 常见问题 (FAQ)

### Q1: 团队模式和单 Agent 模式有什么区别？

**A**:
- **团队模式**：多个 Agent 并行处理，多角度结果
- **单 Agent 模式**：单个 Agent 处理，流式响应

### Q2: 可以同时使用多个团队吗？

**A**: 不可以。每次只能选择一个团队或单个 Agent。

### Q3: 团队执行时间为什么这么长？

**A**: 团队执行是并行处理，时间取决于最慢的 Agent。通常 3-10 秒。

### Q4: 可以查看历史团队对话吗？

**A**: 可以。团队对话会保存到对话历史中，可以随时查看。

### Q5: 如何创建自定义团队？

**A**: 当前版本通过 API 创建，未来版本将提供用户界面。

### Q6: 团队成员数量有限制吗？

**A**: 建议团队规模 2-10 个 Agent。技术上支持更多，但会影响性能。

### Q7: 为什么有些 Agent 失败了？

**A**: 可能原因包括：
- API 调用超时
- 网络问题
- Agent 服务异常
- 其他 Agent 不受影响，会正常返回结果

## 技术细节

### SSE (Server-Sent Events)

团队聊天使用 SSE 技术实现流式响应：

- 单一 HTTP 连接
- 实时推送多个 Agent 结果
- 自动重连机制
- 错误时自动关闭

### 并行执行

使用 Python asyncio 实现：

- asyncio.gather 并行调用
- Semaphore 限制并发数（最多 5 个）
- 单个 Agent 超时 60 秒
- 独立错误处理

### 数据持久化

团队配置存储在 PostgreSQL 数据库：

- `teams` 表：团队信息
- `team_memberships` 表：团队成员关系
- 支持软删除（`is_active` 字段）
